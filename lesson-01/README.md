# 🚨 Lesson 01: 你的应用正在裸奔

> **场景：2024年，Equifax 因未修补的 Apache Struts 漏洞导致 1.47 亿人数据泄露，罚款高达 7 亿美元。**
>
> 你的公司也有一个对外服务的应用——但它没有任何安全防护。

---

## 🎯 CISO 任务简报

你是新上任的 CISO。在第一次安全审计中，你发现了一个令人不安的事实：

> **公司的 Web 应用直接暴露在公网上，没有任何防护层。**
>
> 任何人都能访问它，攻击它，甚至尝试注入攻击。
>
> 而你对这一切一无所知。

你的任务：部署这个应用，理解它有多脆弱，然后问自己——**"如果我是攻击者，我会怎么做？"**

---

## 🏗️ 当前架构

```
  ☁️ 互联网（任何人）
       │
       ▼  ← 没有任何防护！
┌──────────────┐
│ Juice Shop   │  ← 你的应用（已知包含多种漏洞）
│  (Node.js)   │
│  端口 3000    │
└──────────────┘
```

> ⚠️ 这个架构的问题：**你的应用完全暴露，没有防火墙、没有 WAF、没有监控、没有日志分析。**

---

## 🛠️ 动手实验

### 启动你的应用

```bash
docker compose up -d
docker compose ps
```

### 验证应用运行

**浏览器访问：** http://localhost:3000

**命令行验证：**
```bash
curl http://localhost:3000/rest/products
# 如果返回 JSON 产品列表，说明应用正常
```

### 运行攻击演示

```bash
bash attack.sh
```

脚本会展示：
1. ✅ 应用正常响应（确认部署成功）
2. 🔓 公开 API 没有任何访问控制
3. 💉 SQL 注入请求**直达后端**，没有任何拦截

> **关键观察：没有 WAF 时，攻击者的恶意请求不会被阻拦。**

---

## 🧠 CISO 决策时刻

作为 CISO，面对这个局面，你需要回答：

1. **风险识别** — 我的应用已知包含 SQL 注入、XSS 等漏洞，但我没有任何防护。这意味着什么？
2. **攻击面分析** — 谁能访问这个应用？端口 3000 暴露在互联网上，任何扫描器都能发现它。
3. **立即行动** — 我最先应该加什么防护？

### 你的观察记录

| 检查项 | 状态 | 备注 |
|--------|------|------|
| 应用可访问 | ✅ | 说明部署成功 |
| 有 WAF 保护 | ❌ | 恶意请求直达后端 |
| 有日志监控 | ❌ | 被攻击了你也不会知道 |
| 有入侵检测 | ❌ | 端口扫描？毫无感知 |

---

## 📚 知识点

- **OWASP Juice Shop** — OWASP 官方维护的漏洞 Web 应用，包含 SQL 注入、XSS、JWT 漏洞等，专门用于安全教学。
- **攻击面（Attack Surface）** — 系统暴露给潜在攻击者的所有入口点。你的应用暴露越多，风险越大。
- **纵深防御（Defense in Depth）** — 不能只依赖一层防护。本课只有一个应用，后续课程会逐层加固。
- **Docker Network** — 容器间的网络隔离机制，是后续构建安全网络分区的基础。
