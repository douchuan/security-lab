# 🚨 Lesson 05: 暴力破解正在进行——你能把线索拼起来吗？

> **场景：2014 年，eBay 遭到持续性暴力破解攻击，1.45 亿用户数据被泄露。攻击者通过大量登录尝试获得了凭证。**
>
> 事后分析发现：单个失败登录看起来是正常的，但 10 分钟内 5000 次失败登录就是一个明确的攻击信号。
>
> **问题在于：这些日志分散在各个服务器，没有人把它们关联起来。**

---

## 🎯 CISO 任务简报

你是 CISO。你已经部署了 WAF、NIDS 和 HIDS。看起来很不错，对吗？

> **但今天你的 SOC 团队遇到了一个严重问题：**
>
> 攻击者正在对你的系统进行暴力破解。他们每秒钟发送数十次登录请求。
>
> 单个请求在 WAF 看来是正常的（合法的登录页面访问），在 NIDS 看来也是正常的（TCP 连接）。
>
> **只有当你把所有请求放在一起看的时候，攻击模式才浮现出来。**
>
> 但你的日志分散在 4 个不同的地方——你无法关联它们。

你的决定：**部署 SIEM，把所有安全日志集中到一个平台，用关联规则识别攻击链。**

你的任务：部署 Wazuh Manager 作为 SIEM，集中收集、分析、关联所有安全日志。

## 🛠️ 动手实验

### 启动环境（WAF + NIDS + HIDS + SIEM）

```bash
docker compose up -d
docker compose ps
```

### 查看 SIEM 告警

```bash
# 查看 SIEM 运行状态
docker compose logs -f wazuh-manager

# 查看生成的告警
docker compose exec wazuh-manager cat /var/ossec/logs/alerts/alerts.json | tail -10
```

### 运行攻击演示

```bash
bash attack.sh
```

脚本会：
1. ☠️ 对 Juice Shop 发送大量失败登录请求（暴力破解）
2. ⏳ 等待 Wazuh Manager 的关联规则触发
3. 📋 查看暴力破解告警

### 手动暴力破解

```bash
# 快速发送 60 次失败登录请求
for i in $(seq 1 60); do
  curl -s -X POST "http://localhost:80/api/users/login" \
    -H "Content-Type: application/json" \
    -d '{"email":"admin@test.com","password":"wrong'$i'"}' \
    -o /dev/null -w "Attempt $i: HTTP %{http_code}\n"
  sleep 0.2
done

# 查看 SIEM 告警（等待关联规则触发）
docker compose exec wazuh-manager cat /var/ossec/logs/alerts/alerts.json | \
  grep -i "brute\|login\|auth" | tail -5
```

## 🧠 CISO 决策时刻

### SIEM 的核心价值

| 问题 | 没有 SIEM | 有 SIEM |
|------|-----------|---------|
| 单次失败登录 | 正常，无告警 | 正常，无告警 |
| 50 次失败登录/分钟 | 分散在各处，没人知道 | **暴力破解告警！** 🔴 |
| 攻击链分析 | 不可能 | WAF 日志 + NIDS 日志 + HIDS 日志 = 完整攻击路径 |
| 事件响应时间 | 数天到数周 | 数分钟 |

### 你需要思考的问题

1. **"关联分析"到底是什么？** — 单个事件正常，但多个事件在时间、来源、模式上关联起来就构成攻击。eBay 的每个失败登录都正常，但 5000 次/10 分钟就不正常了。
2. **SIEM 如何整合不同日志？** — 统一格式（Decoder 解析）→ 规则匹配（Rule 引擎）→ 关联（时间窗口 + 频率阈值）→ 告警（Severity 分级）。
3. **Decoder + Rule 流程：** 原始日志 → Decoder 解析成结构化数据 → Rule 匹配检测模式 → 生成告警。这是 SIEM 处理的核心流水线。
4. **eBay 的教训是什么？** 如果 SIEM 在运行，它会看到：WAF 记录了登录请求，应用记录了失败日志，SIEM 关联后触发暴力破解告警——响应时间从数周缩短到数分钟。

## 📚 知识点

- **SIEM (Security Information and Event Management)** — 安全信息与事件管理平台。核心功能：日志收集、存储、分析、关联、告警。
- **日志聚合** — 把 WAF、NIDS、HIDS、应用的所有日志统一收集到一个地方。没有聚合，你就是在黑暗中拼图。
- **关联规则** — 基于时间窗口、频率、模式等条件，将多个低级别事件关联为高级别告警。单个失败登录 = Low，50 次/分钟 = Critical。
- **Wazuh Manager** — Wazuh 的核心引擎，负责接收 Agent 日志、执行规则匹配、生成告警。
- **Decoder + Rule** — 处理流水线：原始日志文本 → Decoder 提取字段 → Rule 匹配模式 → Alert 输出。
