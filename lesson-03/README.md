# 🚨 Lesson 03: 有人在扫描你的网络——你能看见吗？

> **场景：2013 年，Target 超市 4000 万信用卡数据被盗。攻击者首先通过端口扫描发现了一个 HVAC（暖通空调）供应商的薄弱入口，然后横向移动到了 Target 的核心网络。**
>
> 如果当时有 NIDS 在监控网络流量，端口扫描行为会被立刻检测到。

---

## 🎯 CISO 任务简报

你是 CISO。WAF 已经部署，Web 攻击被有效拦截。**但今天凌晨，SOC 团队报告了一个令人不安的消息：**

> **有未知 IP 正在对你的服务器进行端口扫描。**
>
> 他们正在探测你开放了哪些端口、运行了哪些服务。
>
> **这不是攻击——这是攻击前的侦察。**

你的决定：**部署 NIDS，让网络层的每一次异常探测都被看见。**

你的任务：部署 Suricata 作为网络入侵检测系统，检测端口扫描和网络层攻击。

## 🛠️ 动手实验

### 启动环境（WAF + NIDS）

```bash
docker compose up -d
docker compose ps
```

### 运行攻击演示

```bash
bash attack.sh
```

脚本会：
1. ✅ 确认 Suricata 正常运行
2. ☠️ 启动一个带 nmap 的临时攻击容器
3. 🔍 对目标执行端口扫描
4. 📋 查看 Suricata 告警日志，展示检测结果

### 手动端口扫描

```bash
# 从宿主机扫描
nmap -sT localhost -p 80,3000

# 查看 Suricata 告警
docker compose exec suricata cat /var/log/suricata/eve.json | grep -i "scan\|alert" | tail -5
```

## 🧠 CISO 决策时刻

### 攻击面分析

| 攻击类型 | WAF 能看到吗？ | NIDS 能看到吗？ |
|----------|---------------|----------------|
| SQL 注入 | ✅ 能 | ❌ 不在网络层 |
| XSS | ✅ 能 | ❌ 不在网络层 |
| 端口扫描 | ❌ 看不到 | ✅ **能！** |
| 网络协议攻击 | ❌ 看不到 | ✅ **能！** |
| DDoS | ❌ 看不到 | ⚠️ 部分能 |

### 你需要思考的问题

1. **NIDS 和 WAF 有什么不同？** WAF 工作在应用层（HTTP），NIDS 工作在网络层（TCP/IP）。它们互补，不替代。
2. **Suricata 如何检测端口扫描？** — 通过检测短时间内对多个端口的连接尝试。这不是基于规则匹配，而是基于行为分析。
3. **为什么 NIDS 需要看到原始流量？** — 因为攻击者可能在 HTTP 之外的协议上发起攻击（SSH、FTP、数据库等）。
4. **Target 的教训是什么？** 攻击者从一个不起眼的供应商入口进入，然后横向移动。如果当时有 NIDS，端口扫描会被检测到，响应时间可能从 **几周** 缩短到 **几分钟**。

### 你的观察记录

| 检查项 | 状态 | 备注 |
|--------|------|------|
| WAF 运行中 | ✅ | 保护 HTTP 层 |
| NIDS 运行中 | ✅ | Suricata 监控流量 |

| 主机层威胁检测 | ❌ | 文件被篡改？不知道 |

## 📚 知识点

- **Suricata** — 高性能开源 IDS/IPS，支持多线程处理。它不只看 HTTP——它看所有网络流量。
- **EVE JSON** — Suricata 的结构化日志输出，每条记录包含告警元数据（源 IP、目标端口、规则 ID、严重级别）。
- **端口扫描检测** — Suricata 通过连接频率和目标端口数量来识别扫描行为。短时间内连接多个端口 = 可疑。
- **ET (Emerging Threats) 规则集** — Suricata 的默认检测规则，涵盖数千种网络攻击特征。
- **NIDS vs WAF** — NIDS 看网络流量（端口扫描、协议异常），WAF 看 HTTP 内容（SQL 注入、XSS）。两者缺一不可。

## 🔜 CISO 的下一步

NIDS 上线了。现在你能看到网络层的异常行为。

> **但攻击者已经进来了怎么办？**
>
> 端口扫描只是侦察阶段。如果攻击者已经获得了某个主机的访问权限，开始篡改文件、植入后门、修改配置……
>
> **NIDS 看不到主机内部发生了什么。**

→ 在下一课中，你将部署 **HIDS（主机入侵检测系统）**，在主机层监控文件完整性、可疑进程和日志异常。

**Target 的教训：** 攻击者用了 **两周** 的时间从入口横向移动到核心系统。如果每一层都有检测，响应时间会大幅缩短。
