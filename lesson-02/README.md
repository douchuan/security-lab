# 🚨 Lesson 02: SQL 注入正在发生——部署你的第一道防线

> **场景：2017 年，Equifax 因为一个未修补的 Apache Struts 漏洞被 SQL 注入攻击，1.47 亿人个人信息泄露。**
>
> 安全团队发现：如果当时部署了 WAF，攻击本可以被拦截。

---

## 🎯 CISO 任务简报

你是 CISO。昨天夜里，安全团队收到了一条令人不安的消息：

> **有攻击者正在对你的 Web 应用进行 SQL 注入攻击。**
>
> 他们试图绕过登录、窃取数据库、篡改数据。
>
> 你的应用直接暴露了——没有任何东西挡在攻击者和数据库之间。

你立刻做了一个决定：**部署 WAF，现在就部署。**

你的任务：在应用前面部署 Nginx + ModSecurity，让所有 HTTP 请求先经过检测再到达应用。

---

## 🏗️ 新架构：WAF 上线

```
  ☠️ 攻击者
       │
       ▼ http://localhost:80
┌──────────────────┐
│ WAF (Nginx +     │  ← 你的新防线：检测并拦截恶意请求
│  ModSecurity)    │     OWASP CRS 规则集已启用
└────────┬─────────┘
         │ 内部网络（攻击者无法直接到达）
         ▼
┌──────────────────┐
│  Juice Shop      │  ← 被保护的应用
└──────────────────┘
```

> ✅ **关键变化：** 所有流量必须通过 WAF。恶意请求会被识别并拦截（返回 403）。

## 🛠️ 动手实验

### 启动 WAF + 应用

```bash
docker compose up -d
docker compose ps
```

### 验证 WAF 工作

**正常请求（应该通过）：**
```bash
curl http://localhost:80
# 应返回正常页面
```

**SQL 注入攻击（应该被拦截）：**
```bash
curl "http://localhost:80/rest/products/search?q=%27%20OR%201%3D1%20--"
# 应返回 403 Forbidden
```

### 运行攻击演示

```bash
bash attack.sh
```

脚本会依次测试：
1. ✅ 正常请求通过 WAF
2. 🛡️ SQL 注入被拦截（403 Forbidden）
3. 🛡️ XSS 攻击被拦截
4. 🛡️ 目录遍历攻击被拦截
5. 📋 查看 ModSecurity 审计日志

## 🧠 CISO 决策时刻

### 攻击 vs 防御对比

| 攻击类型 | 无 WAF (Lesson 01) | 有 WAF (本课) |
|----------|--------------------|---------------|
| SQL 注入 | 💀 直达后端 | 🛡️ 403 拦截 |
| XSS | 💀 直达后端 | 🛡️ 403 拦截 |
| 目录遍历 | 💀 直达后端 | 🛡️ 403 拦截 |

### 你需要思考的问题

1. **WAF 是怎么判断一个请求是恶意的？** — 规则匹配（OWASP CRS）。WAF 不是魔法，它基于已知攻击模式。
2. **WAF 能防御所有攻击吗？** — 不能。WAF 只检测 HTTP/HTTPS 流量。端口扫描、DDoS、0-day 漏洞呢？
3. **WAF 的检测模式 vs 拦截模式：** 检测模式下 WAF 只记录不拦截——这意味着什么风险？
4. **如果规则库不更新会怎样？** — Equifax 的 WAF 当时有规则，但没有及时更新。

### 你的观察记录

| 检查项 | 状态 | 备注 |
|--------|------|------|
| WAF 部署成功 | ✅ | Nginx + ModSecurity |
| 正常流量通过 | ✅ | 业务不受影响 |
| SQL 注入拦截 | 🛡️ | 403 Forbidden |
| XSS 拦截 | 🛡️ | 403 Forbidden |
| 端口扫描检测 | ❌ | WAF 只防护 HTTP 层 |
| 主机层监控 | ❌ | 文件被篡改？不知道 |

## 📚 知识点

- **ModSecurity** — 开源 WAF 引擎，支持 OWASP Core Rule Set (CRS)，检测 SQL 注入、XSS、文件包含等攻击。
- **OWASP CRS** — 预定义规则集，包含数千条规则来识别恶意 HTTP 请求。
- **反向代理** — WAF 作为反向代理，所有流量先经过 WAF 检测，再转发给后端应用。
- **检测模式 vs 拦截模式** — 检测模式只记录告警不阻止请求（用于测试）；拦截模式直接返回 403。

## 🔜 CISO 的下一步

WAF 上线了，Web 攻击被有效拦截。**但攻击者很聪明——他们会换个方向。**

> 如果 HTTP 层被 WAF 挡住了，攻击者可能会进行端口扫描、网络层探测、协议级攻击……
>
> **这些 WAF 看不到。**

→ 在下一课中，你将部署 **NIDS（网络入侵检测系统）Suricata**，在更低层看到攻击者的真实意图。

**Equifax 的教训：** WAF 是重要的，但不能是唯一防线。纵深防御意味着多层检测。
