# 🚨 Lesson 06: 你的作战指挥中心——端到端全链路

> **场景：2020 年，SolarWinds 供应链攻击影响了 18000+ 组织。攻击者在软件更新中植入了后门，潜伏了数月才被检测到。**
>
> 事后审查发现：如果安全团队有一个全景态势感知系统，攻击的每一个阶段都能被看到——但数据分散在几十个系统中，没有人看到全局。
>
> **看得见，才能防得住。**

---

## 🎯 CISO 任务简报

你是 CISO。你已经部署了完整的安全检测链路：

> WAF → NIDS → HIDS → SIEM
>

>
> **但你缺少最后一块拼图：**

> - 攻击从哪里来？

你的决定：**部署 Dashboard，完成整个安全链路的最后一环。**

你的任务：部署 Wazuh Dashboard + OpenSearch，实现端到端的安全态势可视化。

## 🛠️ 动手实验

### 启动完整环境（首次启动需要 2-3 分钟）

```bash
docker compose up -d
docker compose ps
```

### 验证所有组件健康

```bash
docker compose ps --format "table {{.Name}}\t{{.Status}}"
```

你应该看到所有组件都在运行：
- `juice-shop` — 你的应用
- `nginx-modsecurity` — WAF
- `suricata` — NIDS
- `wazuh-agent` — HIDS
- `wazuh-manager` — SIEM
- `wazuh-indexer` — OpenSearch 存储
- `wazuh-dashboard` — Dashboard

### 访问你的指挥中心

- **Wazuh Dashboard**: https://localhost:443
- **默认账号**: admin / admin

> ⚠️ 首次启动时 Dashboard 需要 60-90 秒初始化。请等待所有容器健康后再访问。

### 运行端到端攻击演示

```bash
bash attack.sh
```

脚本会依次执行：
1. 💉 SQL 注入攻击 → WAF 检测
2. 🔍 端口扫描 → Suricata 检测
3. ☠️ 暴力破解 → Wazuh 关联检测
4. ⏳ 等待告警聚合
5. 📋 打印 Dashboard 访问指引

### 手动验证完整链路

**1. SQL 注入（WAF 层）：**
```bash
curl "http://localhost:80/rest/products/search?q=%27%20OR%201%3D1%20--"
# 预期：WAF 返回 403，记录 ModSecurity 告警
```

**2. 端口扫描（NIDS 层）：**
```bash
nmap -sT localhost -p 80,3000,8080
# 预期：Suricata 检测到扫描行为
```

**3. 暴力破解（SIEM 层）：**
```bash
for i in $(seq 1 30); do
  curl -s -X POST "http://localhost:80/api/users/login" \
    -H "Content-Type: application/json" \
    -d '{"email":"admin@test.com","password":"wrong'$i'"}' -o /dev/null
done
# 等待 30 秒后查看 Dashboard 中的暴力破解告警
```

## 🧠 CISO 决策时刻

### 完整防御矩阵

| 攻击类型 | WAF | NIDS | HIDS | SIEM | Dashboard |
|----------|-----|------|------|------|-----------|
| SQL 注入 | 🛡️ 拦截 | | | 📋 记录 | 📊 展示 |
| XSS | 🛡️ 拦截 | | | 📋 记录 | 📊 展示 |
| 端口扫描 | | 🛡️ 检测 | | 📋 记录 | 📊 展示 |
| 文件篡改 | | | 🛡️ 检测 | 📋 记录 | 📊 展示 |
| 暴力破解 | | | | 🛡️ 关联告警 | 📊 展示 |

### 你需要思考的问题

1. **同一个攻击会被多个组件检测到吗？** 会的！SQL 注入同时触发 WAF 告警和应用日志。SIEM 会把它们关联成同一个攻击事件。这就是**纵深防御**的价值——多层检测意味着攻击更难被遗漏。
2. **如果某个组件宕机了会怎样？** 安全链路上会出现缺口。WAF 宕机 → Web 攻击无防护。NIDS 宕机 → 网络层盲区。Dashboard 宕机 → 你看不见但防御还在工作。**所以你需要 Component Health 面板。**
3. **这个环境和真实企业的差距在哪里？** 真实企业有更多组件（防火墙、EDR、SOAR）、更大规模（TB 级日志/天）、更复杂的威胁情报集成。但**核心架构思想是一样的**——分层防御、集中分析、可视化展示。
4. **SolarWinds 的教训是什么？** 攻击者潜伏数月才被发现。如果有实时态势感知，攻击的每个阶段（初始访问、横向移动、数据外泄）都会被 Dashboard 上的告警标记出来。

## 📚 Dashboard 面板说明

| 面板 | 内容 | CISO 视角 |
|------|------|-----------|
| Security Overview | 按严重级别统计的事件数 | 我的安全状态有多糟？ |
| Attack Types | 攻击类型分布饼图 | 我们主要面临哪些威胁？ |
| Event Timeline | 时间轴显示最近安全事件 | 攻击在什么时候最密集？ |
| Source IPs | 攻击来源 IP 列表 | 攻击者从哪里来？ |
| Component Health | 各安全组件在线状态 | 我的防御体系完整吗？ |
| Alert Table | 告警详情（ID、时间、类型、级别） | 我现在需要处理哪些告警？ |

- 编写 ModSecurity 自定义规则，防御特定的攻击模式
