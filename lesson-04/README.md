# 🚨 Lesson 04: 你的服务器文件被篡改了——谁干的？

> **场景：2016 年，Uber 遭到攻击，攻击者获得了 AWS 凭证后修改了内部系统文件，窃取了 5700 万用户的个人信息。Uber 支付了 10 万美元赎金试图掩盖——最终被罚 1.48 亿美元。**
>
> 如果当时有文件完整性监控（FIM），文件的每一次篡改都会被立刻发现。

---

## 🎯 CISO 任务简报

你是 CISO。WAF 和 NIDS 都已部署，但你仍然夜不能寐：

> **如果你的某个服务器已经被攻破了呢？**
>
> 攻击者绕过了 WAF，骗过了 NIDS，现在正在你的服务器上修改文件——植入后门、修改配置、删除日志。
>
> **网络层的检测看不到主机内部发生了什么。**
>
> 你需要一双在主机内部的眼睛。

你的决定：**部署 HIDS，监控每一台主机上的文件变化、可疑进程和系统异常。**

你的任务：部署 Wazuh Agent 作为主机入侵检测系统（HIDS）。

## 🧠 CISO 决策时刻

### 防御层次对比

| 威胁类型 | WAF | NIDS | HIDS |
|----------|-----|------|------|
| SQL 注入 | ✅ | ❌ | ❌ |
| XSS | ✅ | ❌ | ❌ |
| 端口扫描 | ❌ | ✅ | ❌ |
| 网络协议攻击 | ❌ | ✅ | ❌ |
| **文件篡改** | ❌ | ❌ | ✅ **只有 HIDS 能看到** |
| **可疑进程** | ❌ | ❌ | ✅ **只有 HIDS 能看到** |
| **Rootkit 植入** | ❌ | ❌ | ✅ **只有 HIDS 能看到** |

### 你需要思考的问题

1. **HIDS 和 NIDS 的根本区别是什么？** NIDS 从外部看流量，HIDS 从内部看主机。NIDS 像大楼的摄像头，HIDS 像每个房间里的监控。
2. **文件完整性监控（FIM）是什么？** 它记录关键文件的创建、修改、删除。如果 `/etc/passwd` 被改了，FIM 会立刻告警。
3. **Uber 的教训是什么？** 攻击者修改了内部系统的文件和数据，但没有人发现——因为没有文件完整性监控。如果有 FIM，每一次文件篡改都会触发告警。
4. **HIDS 能检测到 0-day 攻击吗？** 可能。因为 HIDS 不只是匹配规则——它监控行为。即使攻击者是新的，异常的文件修改和进程行为仍然可疑。

## 📚 知识点

- **Wazuh Agent** — 部署在受监控主机上的代理，收集日志、文件变化、进程信息。它是你在主机层的"眼睛"。
- **FIM (File Integrity Monitoring)** — 持续监控关键文件的创建、修改、删除。是检测入侵者篡改系统的最有效手段之一。
- **Rootkit 检测** — Wazuh 可以检测系统中可能存在的 rootkit——攻击者用来隐藏自己存在的恶意工具。
- **HIDS vs NIDS：**
  - NIDS：网络层，外部视角，看流量模式
  - HIDS：主机层，内部视角，看系统状态
  - **两者结合 = 完整的威胁可见性**

## 🔜 CISO 的下一步

HIDS 上线了。现在你的每一台主机都有了"眼睛"。

> **但你遇到了一个新问题：你有 4 个安全组件，每个都在产生日志。**
>
> WAF 有 ModSecurity 日志，NIDS 有 Suricata 日志，HIDS 有 Wazuh Agent 日志，应用有自己的访问日志。
>
> **攻击者可能同时触发了多个组件的告警，但你无法把它们关联起来。**
>
> 单个事件看起来无害，但组合起来可能就是一个完整的攻击链。

→ 在下一课中，你将部署 **SIEM**，将所有日志集中到一个平台，进行关联分析和统一告警。

**Uber 的教训：** 如果没有集中的安全日志分析，即使各个组件都检测到了异常，你也不知道它们之间的关联。
